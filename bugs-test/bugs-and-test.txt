BUG #1 [CRITICAL] — Auth Middleware Was a Router, Not Middleware
────────────────────────────────────────────────────────────────────────
File    : server/middleware/auth.js
Severity: CRITICAL — All protected routes were BROKEN (POST/PUT/DELETE)
Impact  : Admin Panel could not create, update, or delete any data.
          Every protected API call would throw "auth is not a function"
          error or route incorrectly, breaking the entire admin workflow.

Root Cause:
  The file server/middleware/auth.js was written as an Express Router
  (with router.post('/login'), module.exports = router) — not as an
  Express middleware function. All route files (projects.js, skills.js,
  certifications.js, experiences.js, education.js, messages.js) import
  it as `const auth = require('../middleware/auth')` and use it as:
      router.post('/', auth, async (req, res) => { ... })
  A Router cannot be used as middleware in this way.

Fix Applied:
  Rewrote server/middleware/auth.js to export a proper Express
  middleware function that:
    1. Reads the JWT from the 'x-auth-token' header
    2. Verifies it using jsonwebtoken
    3. Attaches decoded user to req.user and calls next()
    4. Returns 401 if token is missing or invalid

  Fixed Code:
    const jwt = require('jsonwebtoken');
    const auth = (req, res, next) => {
      const token = req.header('x-auth-token');
      if (!token) return res.status(401).json({ success: false, message: 'No token' });
      try {
        const decoded = jwt.verify(token, process.env.JWT_SECRET || 'default_jwt_secret');
        req.user = decoded;
        next();
      } catch (err) {
        return res.status(401).json({ success: false, message: 'Token is not valid' });
      }
    };
    module.exports = auth;

Note: The login logic (checking ADMIN_EMAIL/.env) was in the wrong file.
  The actual login route is correctly handled in server/routes/auth.js.
  The diagnostic console.logs in the old auth.js have also been removed.

BUG #2 [HIGH] — Skills GET Route: Inconsistent Response Format
────────────────────────────────────────────────────────────────────────
File    : server/routes/skills.js
Severity: HIGH — Admin Panel Skills tab failed to load/display any skills
Impact  : AdminPanel.js line 116 checks:
            if (skillsRes.data.success) setSkills(skillsRes.data.data || [])
          The old skills GET returned a raw array (e.g., [ {...}, {...} ])
          instead of { success: true, data: [...] }. This caused the
          `success` check to always be falsy, setting skills to empty [].

Fix Applied:
  Changed the GET /api/skills response from returning the raw array to
  returning { success: true, data: rows, count: rows.length } to match
  the response format used by all other routes.
  Also added ORDER BY category, name for consistent ordering.
